第一部分

9.1 门控循环单元（GRU）

对应原书第 9.1 节，代码来自原书 PyTorch 版。训练规模缩小了

GRU 有两个门，都是用当前输入和上一步隐状态算出来、经过 sigmoid 落在 0 到 1 之间：

重置门 Rₜ = σ(Xₜ W_xr + H_{t−1} W_hr + b_r)
更新门 Zₜ = σ(Xₜ W_xz + H_{t−1} W_hz + b_z)

先用重置门算一个候选隐状态：Rₜ 接近 0 时，忘掉过去，只看当前输入；接近 1 时就是普通 RNN。

H̃ₜ = tanh(Xₜ W_xh + (Rₜ ⊙ H_{t−1}) W_hh + b_h)

再用更新门在“旧状态”和“候选状态”之间插值。Zₜ 接近 1 时，隐状态几乎原样保留，这一步的输入被跳过；这正是让信息（和梯度）跨越很多步的关键。

Hₜ = Zₜ ⊙ H_{t−1} + (1 − Zₜ) ⊙ H̃ₜ

和原书的不同：原书 256 个隐藏单元、500 轮；这里 64 个、100 轮，电脑上约 40 秒。我在真 PyTorch 上跑过同样的设置：从零实现的 GRU 最后困惑度约 8.7，简洁实现约 7.2。门控网络起步比普通 RNN 慢，轮数多了以后会反超。

第二部分

9.2 长短期记忆网络（LSTM）

对应原书第 9.2 节，代码来自原书 PyTorch 版。训练规模缩小了

LSTM 比 GRU 早（1997 年），多了一个记忆元 Cₜ，专门用来长期保存信息；隐状态 Hₜ 是从记忆元里“读出来”的。三个门：

输入门 Iₜ = σ(Xₜ W_xi + H_{t−1} W_hi + b_i)
遗忘门 Fₜ = σ(Xₜ W_xf + H_{t−1} W_hf + b_f)
输出门 Oₜ = σ(Xₜ W_xo + H_{t−1} W_ho + b_o)

候选记忆元 C̃ₜ = tanh(Xₜ W_xc + H_{t−1} W_hc + b_c)。然后：

Cₜ = Fₜ ⊙ C_{t−1} + Iₜ ⊙ C̃ₜ
Hₜ = Oₜ ⊙ tanh(Cₜ)

遗忘门决定旧记忆留多少，输入门决定新内容写多少，输出门决定这一步对外显示多少。关键在 Cₜ 的更新是加法：∂Cₜ/∂C_{t−1} = Fₜ。只要遗忘门接近 1，梯度沿着记忆元往回传时几乎不衰减。

门控怎样留住记忆

一个 1 维的记忆元。第 1 步写入一个重要信息（C₁ = 1），后面 39 步的输入都是随机噪声。拖动门的大小（假设每一步门的值都一样），看第 1 步的信息到后面还剩多少（实线），以及梯度 ∂C₄₀/∂C₁ 有多大（虚线，对数刻度）。

LSTM 的状态有两个：隐状态和记忆元。

同样缩小到 64 个隐藏单元、100 轮。真 PyTorch 上同样设置的困惑度：从零实现约 10.5，简洁实现约 8.2。

对照你的论文：LSTM 的参数为什么是 4d × d

第 11 天的参数清单里，lstm.weight_ih_l0 的形状是 (256, 64)。现在能看懂了：上面从零实现里的 W_xi、W_xf、W_xc、W_xo 四个 (d, d) 矩阵，PyTorch 把它们（转置后）竖着拼成一个 (4d, d)，一次矩阵乘法算出四个门，再切成四段。顺序是输入门、遗忘门、候选记忆元、输出门。

训练：和论文第 1340 行的 train_kt 一样

Adam、学习率 2×10⁻³（论文第 1237 行给 DKT 设的就是这个）、批量 32、每一步把梯度裁剪到 5、每轮结束在验证集上算 BCE，最后恢复验证集最好的那一轮。前面几天学的东西全在这里了。

在测试集上评估。“上限”是知道每个学生真实掌握状态时的 AUC：就算掌握状态全知道，蒙对和失误也无法预测，所以到不了 1。我在真 PyTorch 上跑同样的代码，DKT 的测试 AUC 约 0.79，上限约 0.86。

看一个测试学生：DKT 每一步对 5 个知识点的预测。答对一个知识点的题，那条线往上走；没练的知识点基本不动。

和论文的差别

你论文的 DKT 还有三样这里没有的东西：（1）策略头 g 和决策损失（第 20 天读代码时细看）；（2）序列按 100 步切窗口，用掩码处理不满的窗口；（3）真实数据集，知识点多（145 到 681 个），学生的行为也远没有 BKT 这么规整。但训练骨架完全一样：编码 → 读出 → gather → BCE → Adam → 裁剪 → 按验证集选检查点。
