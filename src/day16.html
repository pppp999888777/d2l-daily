第一部分

10.5 多头注意力

对应原书第 10.5 节，代码来自原书 PyTorch 版

同一组查询、键、值，用 h 组不同的线性变换投影，各自做一次注意力（每一组叫一个头），把 h 个结果拼起来，再用一个线性层 W_o 混合：

headᵢ = Attention(Q W_qᵢ, K W_kᵢ, V W_vᵢ)
MultiHead = concat(head₁, …, head_h) W_o

不同的头可以学到不同的关注方式：比如一个头看“同一个知识点”，另一个头看“最近几步”。为了不增加计算量，每个头的维度是 num_hiddens / h。

实现上有个技巧：不用循环 h 次，而是把 num_hiddens 维切成 h 段，把“头”这个维度并到批量维度里，一次 bmm 就算完所有头。

10.6 自注意力和位置编码

对应原书第 10.6 节，代码来自原书 PyTorch 版
10.6.1

自注意力

把同一个序列同时当查询、键和值：每个位置都去看序列里所有位置，输出和输入一样长。

10.6.2

比较卷积神经网络、循环神经网络和自注意力

把长度为 n、每个位置 d 维的序列变成同样长度的序列，三种做法比较如下（原书表格）：

计算量顺序操作（能不能并行）最长路径（远处信息要走几步）
卷积（核大小 k）O(knd²)O(1)O(n/k)
循环神经网络O(nd²)O(n)：必须一步一步算O(n)
自注意力O(n²d)O(1)：所有位置同时算O(1)：任意两个位置直接相连

自注意力的好处：可以并行，远处的信息一步就到。代价：计算量随序列长度的平方增长。KT 里一个窗口 100 步，n² = 10⁴，完全可以接受。

对照你的论文：DKT 和 SAKT 的区别

DKT 用 LSTM，第 100 题的信息要从第 1 题开始一步步传过来，中间可能被遗忘（第 14 天的门控只是缓解）。SAKT 用自注意力，预测下一题时直接回头看所有做过的题，挑相关的看：比如下一题考“分数加法”，就重点看以前做过的分数加法题。

10.6.3

位置编码

自注意力对位置是“看不见”的：把序列打乱顺序，每个位置的输出只是跟着换位置，值完全不变。可是顺序很重要（昨天做对和一个月前做对，意义不同）。所以要给每个位置加一个位置编码。原书用正弦和余弦：第 i 个位置、第 2j 和 2j+1 维是

p_{i,2j} = sin(i / 10000^{2j/d})，p_{i,2j+1} = cos(i / 10000^{2j/d})

第 6 到 9 列：越往后的列，频率越低（波越长）。

原书的类比：二进制数里，最低位每 1 个数变一次，第二位每 2 个数变一次，第三位每 4 个数变一次。位置编码也是这样，只是用连续的正弦波代替 0 和 1。

位置编码能表示“相隔多远”

原书 10.6.3.2 节说：位置 i + δ 的编码可以由位置 i 的编码经过一个只和 δ 有关的线性变换得到，所以模型容易学到“相对位置”。直观地看：两个位置编码的点积只和它们隔了多远有关。选一个位置 i，下图是它和所有位置的编码的相似度（点积，除以维度）。

补充：SAKT 的因果自注意力

本页补充，对照你论文 experiment.py 第 995 行的 causal_attn 和第 1141 行的 SAKT

KT 里有一条铁律：预测第 t+1 题时，只能用第 t 题及以前的记录。自注意力默认每个位置都能看所有位置，所以要加因果掩码：第 i 个查询看第 j 个键时，如果 j > i（在未来），就把分数设成很大的负数。

第 1 行只能看第 1 个位置（权重 1），第 2 行平分给前 2 个，第 5 行平分给全部 5 个。画成热图，右上角全是 0：

SAKT 预测下一题时在看什么

一个学生做了 10 道题（上面一排，格子里写着知识点和对错）。选下一题考哪个知识点。查询是“下一题的知识点”，键是“做过的题的知识点 + 位置”，值是“做过的题的对错”。这里用一个手工设计的打分：同一个知识点加分，越近加分越多（模拟模型学到的东西）。柱子是注意力权重，预测是值（对 = 1，错 = 0）的加权平均。

对照你的论文：causal_attn 逐行看

def causal_attn(Q, Kt, V, qpos, heads, decay=None):     # 第 995 行
    B, Tq, M, d = Q.shape
    T = Kt.shape[1]; dh = d // heads                     # 每个头 dh = 64 / 2 = 32 维
    q = Q.reshape(B, Tq, M, heads, dh).permute(0, 3, 1, 2, 4)   # 和 transpose_qkv 一样：切头
    k = Kt.reshape(B, T, heads, dh).permute(0, 2, 1, 3)
    v = V.reshape(B, T, heads, dh).permute(0, 2, 1, 3)
    s = torch.einsum("bhtmd,bhjd->bhtmj", q, k) / math.sqrt(dh)   # 缩放点积
    jpos = torch.arange(T, device=Q.device)
    dist = qpos.view(-1, 1) - jpos.view(1, -1)          # 查询位置减键位置
    ...
    s = s.masked_fill((dist < 0).view(1, 1, Tq, 1, T), -1e9)    # 键在未来：因果掩码
    a = torch.softmax(s, -1)
    o = torch.einsum("bhtmj,bhjd->bhtmd", a, v)          # 加权求和
    return o.permute(0, 2, 3, 1, 4).reshape(B, Tq, M, d)   # 和 transpose_output 一样：拼回去

和今天的 MultiHeadAttention 是同一个东西：einsum 只是 bmm 的另一种写法。SAKT（第 1141 行）里：键和值来自做过的题 self.iemb(sk + self.K * rs.long()) 加上位置；查询来自下一题的知识点 self.qemb(q)；heads=2；位置编码用的是可学习的 nn.Embedding(maxlen, d)，不是今天的正弦函数，两种都常见。被省略的那两行是 AKT 用的“距离衰减”（decay），明天讲。
